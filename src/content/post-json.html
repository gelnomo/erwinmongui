Taming the data jungle: JSON as the contract between your systems and AI.

AI runs on data that rarely fits neatly into rows and columns. In 2024 I wrote about JSON as a practical tool for that problem. Since then it has become more than that: JSON is now how software and AI models talk to each other, from structured outputs and tool calls to memory and model configuration.

By Erwin MonguiFirst published February 6, 2024Updated September 23, 20267 min readOriginally on LinkedInLeer en español
In short

Define a JSON Schema for what you expect from a model, ask the model to follow it, and validate every response before using it. The same pattern powers structured outputs, tool calling and agent protocols like MCP. Keep conversational memory and model settings in versioned JSON too, so your AI system stays predictable and easy to debug.

Beyond rows and columns

Edgar F. Codd's relational model still underpins most business systems, and for good reason. But AI applications work with much more than tables:

  • Structured data: orders, customers and listings in relational databases.
  • Semi-structured data: JSON from APIs, events and logs, where fields vary from record to record.
  • Unstructured data: free text, documents and images.

Real-world data also breaks the assumptions relational design relies on. In areas like biometrics or online advertising, there is often no reliable unique identifier, so records have to be matched by probability instead of by key. Handling this well takes solid data wrangling, and increasingly, AI models that can read and structure messy input.

Why JSON became the language of AI applications

JSON is lightweight, human-readable and supported everywhere. Those qualities made it the default for web APIs. For AI, it solves a bigger problem: turning a model's free-form text into something software can rely on.

1. Structured outputs

Major model providers can now constrain a model's answer to a JSON Schema you supply. Instead of parsing text and hoping, you get a response in the shape you defined, which you then validate in code. In Python, Pydantic is the usual way to define the schema and check the result; in TypeScript, Zod plays the same role.

2. Tool calling and agents

When a model decides to call a function, such as searching a database or creating a ticket, it produces the arguments as JSON that matches the tool's schema. Agent frameworks like LangGraph and Pydantic AI are built around this. The Model Context Protocol (MCP), now a common way to connect AI assistants to tools and data, uses JSON-RPC messages under the hood.

3. Conversational memory

A useful assistant remembers context: your preferences, the last thing you asked, what is still unresolved. Storing that as a small, well-defined JSON object per user or session keeps memory explicit and easy to inspect. For long histories, pair it with vector search (for example pgvector in PostgreSQL, or Elasticsearch) to retrieve only the relevant pieces.

4. Model configuration and reproducibility

Deep learning models run on tensors, but everything around them is configuration: architecture settings, training hyperparameters, fine-tuning parameters and evaluation results. Keeping these in JSON makes experiments transparent and repeatable. The Hugging Face ecosystem works this way: a model ships its settings in a config.json file next to its weights, usually stored as safetensors. Tools like MLflow track runs and parameters in the same spirit.

A worked example: natural language search

At Fincaraiz we built search that understood conversational queries and local place names (I describe it in the migration case study). With today's models, the first step of that kind of search, turning a sentence into filters, takes a few lines. First, define what a search looks like:

from typing import Literal
from pydantic import BaseModel, Field

class PropertySearch(BaseModel):
    operation: Literal["buy", "rent"]
    property_type: Literal["apartment", "house", "lot", "commercial"]
    bedrooms: int | None = None
    location: str = Field(description="Neighborhood, city or landmark, as the user wrote it")
    max_price_cop: int | None = Field(None, description="Maximum price in Colombian pesos")

schema = PropertySearch.model_json_schema()  # send this to the model as the required output format

A user types: "3-bedroom apartment to buy in Chapinero, under 500 million". With structured outputs, the model returns:

{
  "operation": "buy",
  "property_type": "apartment",
  "bedrooms": 3,
  "location": "Chapinero",
  "max_price_cop": 500000000
}

Then validate it before it touches your search engine:

search = PropertySearch.model_validate_json(model_response)
# raises a clear error if a field is missing or has the wrong type

The model handles the language. Your code and your data still handle the rest: resolving "Chapinero" to its exact boundary on the map, applying the filters and ranking the results. That split is what makes AI features reliable.

Practices that keep it reliable

  • Schema first. Agree on the JSON shape before writing prompts or code.
  • Validate everything. Treat model output like user input: check it, and have a fallback when it fails.
  • Version your schemas. Changing a field is a breaking change for anything downstream.
  • Keep sensitive data out. Don't store personal data in memory objects or logs unless you need it and protect it.
  • Log inputs and outputs. Real examples become the test set for your evaluations.

AI coding assistants help here too. They are good at drafting schemas, sample payloads, test fixtures and transformation scripts from a short description, which removes much of the tedious work. The design decisions, and the review, stay with the engineer.

The takeaway

Handling diverse data well was the foundation of AI work in 2024, and it still is. What has changed is that JSON now sits at the center of it, as the contract between your systems and the models they use. Whether you are building an assistant, a recommendation system or an agent, getting that contract right is what turns an impressive demo into software people can depend on.
